# 工具实现说明

本文件解释 `craftreview` 如何把 `docs/业务规程.md` 的规则落成可执行逻辑。手册是权威来源；当两者冲突时以手册为准，并在 `craftreview/config.py` 中报错，而不是默默放宽阈值。

## 手册规则与实现位置

| 手册要求 | 实现 |
| --- | --- |
| 按片源家族隔离训练、校准、检验 | `families.py` 合并同源家族；`models.py` 的 `_isolation_violations` 检测跨组，发现即整场评估无效，不输出总体准确率 |
| 两个不同家族的独立复核样本 | `eligibility.py` 按证据组（家族合并后）计数；每个家族只计一次 |
| 细类精度下界达到 0.80 | `stats.py` 单侧 Wilson 下界；样本不足时下界接近 0，不会被点估计抬高 |
| 只有父类一致的双评不得用于细类 | `resolve_gold` 把 `coarse_only_agreement` 单列，不计入 `fine_by_family` |
| 示意动作误标成规范工序属高成本 | `courses.csv` 的 `severity` 决定成本；`select_model` 先比高代价细类错误次数 |
| 细类只在特定器具及工序上下文可区分 | 证据键含 `context`；目录 `scope_notes` 限定适用范围 |
| 双评核对判定同一表演会影响后续统计 | `resolve_families` 合并家族；`findings.csv` 使依赖它的细类资格失效，核对之后的新复核可重新积累 |

## 未在手册中明确、工具采用的保守口径

以下做法是为避免误判而设的更严处理，均会在报告中标注：

- **单一非训练家族**：若某细类在语料中只有一个非训练家族，补复核时间也无法满足“两个家族”，工具不把它排入复核，而是提示征集片源。
- **支系不一致**：复核记录的传承支系与片段不一致时降级为父类结论。
- **技能栏未单列细类**：只提示补登记，不否定复核人的细类判断，因为手册未要求细类必须由同名技能的人签署。
- **检索范围**：模型评估默认只用 `test` / `holdout`；`train` 只用于拟合，`valid` 不参与最终报告。
- **拒判成本**：拒判按两倍回退成本计，促使模型在边界不清时明确拒判而不是硬猜。

## 输出结构

`python3 -m craftreview analyze --json` 输出：

- `summary`：可上线细类、继续沿用父类、所选模型、警告。
- `evidence`：每个 `(工序, 地域, 器具, 细类)` 的家族数、精度下界、阻塞原因与推荐粒度。
- `family_isolation`：跨组违例。
- `models` / `selection`：逐模型覆盖、拒判、成本、逐小类结果与选型排名。
- `migration`：目录变化与逐章节动作（换说明 / 继续引用 / 阻塞）。
- `ungradable`：仍无法升级的课件。
- `review_plan`：本期排期、未排任务、无需重复复核的任务、下一期能力缺口。
